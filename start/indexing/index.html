统计与搜索收录

分开看访问、抓取、收录、曝光和点击。

S 计划上站路线05 / 08 · 更新于 2026.10.04

本阶段目标：能够观察用户访问，并让搜索系统发现正式页面。

最小路线：接入一套访问统计和 Google Search Console；核对正式地址、抓取限制与 sitemap，再检查主页面；记录提交日期，随后定期观察，不把提交成功当作已经收录。

完成标准：统计可见一次测试访问，GSC 验证成功，主页面检查及 sitemap 提交有记录。

操作步骤

步骤做什么完成判据常见卡点
接上访问统计创建统计项目并安装代码，按实际用户地区及平台要求处理必要的告知与选择，再用测试访问核对。能在统计后台看到测试访问，知道自己的测试应如何识别。不要同时接多套统计增加噪声，也不要把测试访问当真实增长。
验证 GSC 所有权选择适合的域名或网址前缀资源，按提示添加 DNS 或验证文件，保留验证配置。后台显示验证成功，资源覆盖实际正式网址。http、https、www 和子路径范围不同，别在错误资源里看数据。
检查页面可抓取检查 robots.txt、noindex、canonical、状态码及无需登录的正文；测试环境与正式环境分开处理。主页面可访问，未误设禁止索引，规范地址指向正式页面。抓取允许、索引允许与已被收录是三件事。
提交 sitemap 与主页面生成只含正式可索引网址的 sitemap，在 GSC 提交并用网址检查查看主页面状态。提交和检查结果已记录，发现错误有具体修复项。sitemap 被读取不等于全部页面收录，也不承诺收录时间。
建立观察记录定期记录索引状态、搜索词、曝光、点击和统计中的功能使用；注明时间范围与更新延迟。能区分没被发现、未索引、有曝光无点击和访问后不用功能。新站数据不足时先记录，别据一天波动大改整站。
